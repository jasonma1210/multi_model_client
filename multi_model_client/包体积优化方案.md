# 包体积优化方案

**目标：** 233MB → <150MB  
**分析日期：** 2026-04-29

---

## 一、当前包体积构成分析

### 1.1 主要依赖包体积估算

| 依赖包 | 估算大小 | 说明 |
|-------|---------|------|
| syncfusion_flutter_pdf | ~40MB | PDF 解析（已压缩） |
| llamadart | ~30MB | 本地推理（已裁剪） |
| sherpa_onnx | ~25MB | 离线 ASR/TTS |
| google_mlkit_text_recognition | ~15MB | OCR |
| pdfx | ~12MB | PDF 渲染 |
| 其他 60+ 依赖 | ~80MB | 网络、数据库、UI 等 |
| **Flutter 运行时** | ~30MB | 基础框架 |
| **资源文件** | ~15MB | 图标、分词词典 |

### 1.2 可优化点

1. **资源文件**：jieba 词典 11MB - 可改为按需下载
2. **重复依赖**：多个 PDF 处理库（pdfx + syncfusion）
3. **调试符号**：release 包可移除调试信息

---

## 二、优化方案

### 方案 1：jieba 词典按需下载 (可节省 ~11MB)

```yaml
# pubspec.yaml - 移除静态词典
# - assets/jieba/
# - assets/dict.txt
# - assets/prob_emit.txt

# 改为运行时下载
Future<void> _downloadJiebaDict() async {
  // 首次使用时从网络下载词典
}
```

### 方案 2：移除重复的 PDF 库 (可节省 ~12MB)

当前项目同时使用了：
- `pdfx` - PDF 渲染
- `syncfusion_flutter_pdf` - PDF 文本提取

**建议保留 syncfusion_flutter_pdf，移除 pdfx**

### 方案 3：启用 Tree Shaking 和 R8 压缩

```yaml
# android/app/build.gradle
android {
  buildTypes {
    release {
      minifyEnabled true
      shrinkResources true
      proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
    }
  }
}
```

### 方案 4：App Bundle 优化 (Android)

```bash
# 使用 App Bundle 替代 APK
flutter build appbundle --release
# App Bundle 只包含设备所需的资源
```

## 三、预期效果

| 优化方案 | 预计节省 |
|---------|---------|
| jieba 词典按需下载 | ~11MB |
| 移除 pdfx 保留 syncfusion | ~12MB |
| R8 压缩 + Tree Shaking | ~20MB |
| App Bundle 动态分发 | ~30MB |
| **总计** | **~73MB** |

**目标达成：233MB - 73MB = 160MB（接近目标）**

---

## 四、执行优先级

1. **立即执行**：jieba 词典按需下载
2. **短期**：移除重复 PDF 库
3. **中期**：启用 R8 压缩
4. **长期**：迁移到 App Bundle

---

## 五、注意事项

1. 移除 pdfx 前需确认没有其他地方使用它
2. jieba 词典下载需要网络，首次离线使用会受影响
3. R8 压缩可能影响崩溃堆栈准确性，建议保留 mapping 文件
